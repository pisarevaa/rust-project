# rust-project

#  Домашнее задание 1
Заготовка для библиотеки "Умный дом"
##  Цель
создать заготовку для библиотеки «Умный дом» и написать пример, демонстрирующий её функционал.

## Описание/Пошаговая инструкция выполнения домашнего задания:
Библиотека и пример использования реализованы в одном package.

## Для библиотеки:

- Реализована в виде lib крейта.
- Опишите тип: умный термометр. Тип должен предоставлять следующий функционал:
    - Конструктор, принимающий значения полей.
    - Возвращать значение текущей температуры (произвольное число).
- Опишите тип: умная розетка. Тип должен предоставлять следующий функционал:
    - Конструктор, принимающий значения полей.
    - Включение/выключение + возможность узнать текущее состояние.
    - Возвращать текущую мощность: если выключено — ноль, иначе произвольное число.
- Опишите тип: умное устройство. Тип должен содержать одно из устройств (умный термометр или розетку) и предоставлять следующий функционал:
    - Выводить в стандартный вывод сообщение о состоянии устройства.
- Опишите тип: комната, содержащая массив умных устройств. Тип должен предоставлять следующий функционал:
    - Конструктор, принимающий массив устройств.
    - Можно получить ссылку на устройство по указанному индексу.
    - Можно получить мутабельную ссылку на устройство по указанному индексу.
    - Выводить в стандартный вывод отчёт о всех устройствах в комнате.
- Опишите тип: умный дом, содержащий массив комнат. Тип должен предоставлять следующий функционал:
    - Конструктор, принимающий массив комнат.
    - Можно получить ссылку на комнату по указанному индексу.
    - Можно получить мутабельную ссылку на комнату по указанному индексу.
    - Выводить в стандартный вывод отчёт о всех комнатах.
- Размеры массивов можно выбрать произвольно.
- В случае, если указан индекс, выходящий за пределы массива, приложение должно аварийно завершаться (макрос panic!()).

## Для примера использования
- Реализована в виде bin крейта.
- Создайте экземпляр умного дома и выведете отчёт о его содержимом.
- Для уже созданного экземпляра дома выключите умную розетку в одной из комнат. Снова выведите отчёт.

## Критерии оценки
Package успешно собирается.
Приложение-пример успешно выполняется и выводит отчёт о доме.
Команды cargo clippy и cargo fmt --check не выводят ошибок и предупреждений.
Присутствуют и успешно выполняются модульные тесты.

# Домашнее задание 3
Дорабатываем умные устройства
## Цель
описать для умной розетки и умного термометра логику взаимодействия с удалённым устройством и написать имитаторы устройств для тестирования.

## Описание/Пошаговая инструкция выполнения домашнего задания
1. Для типа умной розетки:
- Функционал не изменяется: включение/выключение + запрос мощности.
- Взаимодействие организовано синхронно, через TCP.
- Розетка может использовать как реальный TCP-обмен, так и имитировать реальную работу (для тестов).

2. Для имитатора умной розетки:
- Читает адрес для приёма TCP-соединений из аргументов командной строки.
- Реализован с использованием неблокирующего сетевого взаимодействия.
- Хранит состояние розетки.
- Позволяет управлять розеткой множеству клиентов одновременно.

3. Для умного термометра
- Функционал не изменяется: возвращает температуру.
- Получает значения температуры в виде UDP-пакетов в параллельном потоке.
- Параллельный поток запускается при создании объекта термометра и завершается при уничтожении этого объекта.
- Объект термометра возвращает последнее полученное значение температуры.
- Термометр может имитировать удалённое получение данных о температуре (для тестов).

4. Для имитатора умного термометра
- Реализован с использованием неблокирующего сетевого взаимодействия.
- Читает адрес для отправки UDP-пакетов и временной период отправки из файла.
- Отправляет произвольное значение температуры на указанный адрес с указанной периодичностью.

5. Добавлен дополнительный пример умного дома с розетками и термометрами, которые работают с имитаторами. Данный пример должен запускаться и
- Выводить отчёт о состоянии дома, если имитаторы запущены.
- Сообщать об ошибке, если устройству не удалось получить данные.

## Критерии оценки:
- Package успешно собирается.
- Приложение-пример успешно выполняется.
- Команды cargo clippy и cargo fmt --check не выводят ошибок и предупреждений.
- Присутствуют и успешно выполняются модульные тесты.

Примеры из ДЗ4 (билдер, компоновщик отчетов, наблюдатели комнаты):

Пакеты из ДЗ5 (умная розетка с Си ABI):

- `crates/smart-socket-ffi` — библиотека; при сборке создает Rust-библиотеку
  (`libsmart_socket_ffi.rlib`), статическую (`libsmart_socket_ffi.a`) и
  динамическую (`libsmart_socket_ffi.so`/`.dylib`/`.dll`) библиотеки с Си ABI.

- `crates/socket-dynamic-app` — загружает динамическую библиотеку в runtime
  через `libloading`. Путь к библиотеке можно задать переменной

имитатором из ДЗ3:

```sh
cargo run -p socket-static-app
cargo run -p socket-dynamic-app

cargo run -p socket-dynamic-app -- 127.0.0.1:8181
```

```sh

cargo run --bin thermometer-simulator -- thermometer-simulator.conf
cargo run --example remote_house
```

```sh

```

Если имитаторы не запущены, пример не падает: вместо показаний в отчете
появляется причина, по которой их не удалось получить. В доме есть комната
«Кладовка» с заведомо недоступными устройствами — она показывает обработку
ошибки даже при запущенных имитаторах.

## ДЗ6: веб-сервис умного дома

### Архитектура

```
┌──────────────── home-desktop (Tauri) ────────────────┐            ┌──── home-backend ────┐
│  UI: ui/index.html, main.js, styles.css               │            │  axum, REST API      │
│        │ invoke("list_rooms", …)                      │   HTTP     │  Store в памяти      │
│        ▼                                              │  (JSON)    │  (RwLock)            │
│  #[tauri::command] → BackendClient (reqwest) ─────────┼──────────► │                      │
└───────────────────────────────────────────────────────┘            └──────────────────────┘
                        общие типы запросов и ответов: home-api
```

Пакеты workspace:

- `crates/home-api` — общие типы API (`Room`, `RoomSummary`, `Device`,
  `NewRoom`, `NewDevice`, `HouseReport`, `ErrorResponse`), которыми
  пользуются и backend, и desktop-клиент.
- `crates/home-backend` — backend-сервис на axum. `store.rs` хранит дом в
  памяти и проверяет данные, `routes.rs` описывает REST API, `error.rs`
  превращает ошибки в JSON `{ "code": …, "message": … }` с нужным HTTP-статусом.
- `crates/home-desktop` — desktop-приложение на Tauri 2. Интерфейс написан на
  HTML/CSS/JS без сборщика и обращается только к командам Tauri через
  `window.__TAURI__.core.invoke`. Команды (`#[tauri::command]` в `src/lib.rs`)
  выполняют HTTP-запросы к backend через `BackendClient` (`src/client.rs`).
  Ошибки команд приходят в интерфейс как `{ kind, message }`, где `kind` —
  `unavailable`, `not_found`, `validation`, `conflict`, `server` или `config`.

Устройство содержит идентификатор, идентификатор комнаты, название, тип
(`socket`, `thermometer`, `light`) и состояние (`on`, `off`, `offline`).

### REST API

| Метод    | Путь                                       | Описание                          |
|----------|--------------------------------------------|-----------------------------------|
| `GET`    | `/health`                                  | проверка, что сервис жив          |
| `GET`    | `/api/rooms`                               | список комнат с числом устройств  |
| `POST`   | `/api/rooms`                               | добавить комнату `{ "name" }`     |
| `GET`    | `/api/rooms/{room_id}`                     | комната вместе с устройствами     |
| `DELETE` | `/api/rooms/{room_id}`                     | удалить комнату с устройствами    |
| `GET`    | `/api/rooms/{room_id}/devices`             | устройства комнаты                |
| `POST`   | `/api/rooms/{room_id}/devices`             | добавить устройство `{ "name", "kind", "status" }` (`status` по умолчанию `off`) |
| `GET`    | `/api/rooms/{room_id}/devices/{device_id}` | устройство                        |
| `DELETE` | `/api/rooms/{room_id}/devices/{device_id}` | удалить устройство                |
| `GET`    | `/api/report`                              | отчет о доме                      |

Отчет содержит число комнат и устройств, количество устройств по типам и по
состояниям, а также список комнат с числом устройств в каждой.

Ошибки:

- `404 not_found` — нет комнаты, устройства (в том числе при добавлении
  устройства в несуществующую комнату) или маршрута;
- `422 validation` — пустое или слишком длинное (больше 64 символов) название,
  некорректный JSON, неизвестный тип или состояние, нечисловой id в пути;
- `409 conflict` — комната с таким названием уже есть или в комнате уже есть
  устройство с таким названием (без учета регистра).

Если backend недоступен, desktop-клиент сообщает об этом в интерфейсе
(ошибка `unavailable`) и предлагает повторить запрос.

### Конфигурация

| Переменная               | Где используется | По умолчанию            | Назначение                         |
|--------------------------|------------------|-------------------------|------------------------------------|
| `SMART_HOME_ADDR`        | `home-backend`   | `127.0.0.1:3000`        | адрес, на котором слушает сервис   |
| `SMART_HOME_BACKEND_URL` | `home-desktop`   | `http://127.0.0.1:3000` | адрес backend-сервиса для клиента  |

Desktop-клиент обращается к backend напрямую, игнорируя системный прокси
(`http_proxy` и т. п.), так как адрес backend задан явно.

### Запуск backend-сервиса

```sh
cargo run -p home-backend
# или на другом адресе
SMART_HOME_ADDR=0.0.0.0:8080 cargo run -p home-backend
```

Пример запросов:

```sh
curl -X POST localhost:3000/api/rooms -H 'content-type: application/json' -d '{"name":"Кухня"}'
curl -X POST localhost:3000/api/rooms/1/devices -H 'content-type: application/json' \
     -d '{"name":"Чайник","kind":"socket","status":"on"}'
curl localhost:3000/api/report
```

Сервис завершается по Ctrl+C. Данные хранятся в памяти и пропадают при
перезапуске.

### Запуск desktop-приложения

Нужен Rust и системные зависимости Tauri
(https://v2.tauri.app/start/prerequisites/; на macOS достаточно Xcode Command
Line Tools). Tauri CLI и Node.js не нужны: интерфейс — статические файлы из
`crates/home-desktop/ui`, они встраиваются в бинарник при сборке.

```sh
# во втором терминале, при запущенном backend
cargo run -p home-desktop
# с другим адресом backend
SMART_HOME_BACKEND_URL=http://127.0.0.1:8080 cargo run -p home-desktop
```

В приложении можно посмотреть и добавить комнаты, открыть комнату со списком
ее устройств, добавить устройство, посмотреть сведения об устройстве, удалить
комнату или устройство (удаление подтверждается повторным нажатием) и открыть
отчет о доме кнопкой «Отчет о доме». Во время запросов панели показывают
индикатор загрузки, ошибки выводятся в панели с кнопкой «Повторить», в форме
или во всплывающем сообщении.

### Тесты

```sh
cargo test -p home-backend   # модульные тесты хранилища и интеграционные тесты REST API
cargo test -p home-desktop   # тесты HTTP-клиента desktop-приложения против backend
cargo test                   # все тесты workspace
```

Интеграционные тесты (`crates/home-backend/tests/api.rs`) поднимают сервис на
свободном порту и по HTTP проверяют создание и получение комнаты, список
комнат, создание и получение устройства, список устройств комнаты, удаление
устройства и комнаты, отчет о доме и ошибочные запросы (несуществующая
комната, устройство в несуществующей комнате, ошибки валидации, дубликаты,
неизвестный маршрут).
